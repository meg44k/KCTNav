# KCTナビ 提案内容

一次審査（アイデアコンペ）で提出した提案の内容。作るものの基準。根拠は提案書と発表スライド（`docs/materials/`）。

- 課題と要求は [requirements.md](requirements.md)、審査員からの指摘は [review-feedback.md](review-feedback.md) を参照
- 元資料はAIで作成したため表記の揺れがある。揺れに意味の違いはない

## 原因の捉え方

- 迷う原因は「棟の位置が分からない」だけではなく、**平面の地図には、高さと階のつながりが描けない**こと
  - 例: 1号館3階から渡り廊下を渡ると6号館2階
- 迷いは2段階: **どの棟か分からない** → **棟に着いても何階か分からない**
- アプリを作るうえでの壁: **建物の中ではGPSが効かない**

## 目的と成功の目安

**スマホ1台で、「どの棟の、何階の、どの部屋か」まで、人に聞かずにたどり着ける**

| 目安 | 内容 |
| --- | --- |
| 探す | 部屋名・先生名・施設名から、**10秒以内**に目的地を地図に出せる |
| 分かる | 目的地の棟と階・行くべき方向が、地図を読むのが苦手な人でもひと目で分かる |
| 着く | 校門から目的の部屋まで、途中で人に道を聞かずに着ける |

## 案内の流れ

1. **探す**: 検索するか、案内板・部屋の前のQRコードから開く。目的の棟が地図で光る
2. **建物の外**: コンパスの矢印が**棟の入口**（部屋ではない）の方角を指し、残りの距離を表示
3. **入口で切り替え**: 入口に近づくと（またはQRを読むと）自動で文字案内と3Dに切り替わる

入口に着いた後の案内イメージ:

> ○号館に着きました／次は 階段で2階へ
> 1. 入口を入って左の階段を上がる
> 2. 2階で右へ。手前から3つ目の部屋
>
> ※ 3D地図では○号館の2階だけを光らせて一緒に表示

## 画面と表示のルール

- **インストール不要**: Webページ。QRコードを読むかURLを開くだけ
- **最初は2D、必要なときだけ3D**: 階が関係する目的地を選んだときだけ、自動で3Dに切り替える
- **見るものを減らす**: 目的の棟だけ色を付け、残りはグレー。よく使うボタンは「全体表示」「現在地」「2D/3D」の3つと、棟のタップだけ
- **つながりで説明する**: 「B棟2階」とだけ言わず、「A棟3階から渡り廊下を渡ると着く」
- **ふだんの言葉で**: 「北東」ではなく「階段を上がって右」。方角はコンパスの矢印で見せる
- **色だけに頼らない**: 光らせた棟には必ず棟名と「2F」などの文字も付ける
- **説明を読まなくても使える**

## 利用シーン

どの人も同じ流れで使い、違うのは最初の入口と表示の設定だけ。

| 利用者 | 入口・設定 | 主に助けになる機能 |
| --- | --- | --- |
| オープンキャンパスに来た中学生と保護者 | 受付や正門の案内板のQR | 見学コース、コンパス案内 |
| 4月の新入生 | 部屋名で検索、教室の前のQR | 3D（渡り廊下の近道）、文字案内 |
| 車いすの来客 | 「段差なし」をオン | 段差なし経路（エレベーター・スロープ） |
| 留学生・海外からの来客 | 英語表示に切り替え | 英語表示、言葉に頼らない矢印と3D |

## 地図データ

- キャンパスの3Dモデル: 主な**12棟**（1号館〜8号館、福利施設、体育館、第2工場、ものづくりセンター（第1工場））

## 難しい点と対策

| 難しい点 | 対策 |
| --- | --- |
| 屋内の現在地はGPSで取れない | 入口まではコンパス案内、屋内はQRや入口からの文字案内（発信機などの機器は使わない） |
| 全棟の部屋を一度に入れるのは大変 | 既存の部屋の一覧（掲示や校内図）をもとに、棟単位で少しずつ登録・公開 |
| 管理画面を外から操作されたくない | 管理画面は学内ネットワークからしか開けないように制限。来校者用の地図は学外回線からも使える |
| 先生の部屋をどこまで載せるか | 学校と相談し、部屋ごとに公開範囲を選べるようにする |
| 方位センサーの誤差 | 方角は「おおよそ」として表示し、目印（棟名）と合わせて使う |

## 運用

一番大事にすること: **データを直すのにプログラミングが要らない**

- ログインした教職員が、ブラウザの管理画面から部屋・先生・場所を直す
  - 項目: 部屋名、種類、棟・階、担当、場所（地図を押して決める）
  - 保存すると検索と地図にすぐ反映
  - 役割ごとに触れる範囲を分ける（例: 学科ごとに自分の学科の部屋だけ）
  - 想定する更新: 年度替わりの部屋替え、先生の異動、実験室の用途変更
- QRコードは部屋に結び付けるので、担当が変わっても貼り替え不要
- 費用はサーバー代程度。学校のサーバーかクラウドの無料枠で動かせる規模を想定
- ソースコードと手順書（建物データの直し方、サーバーの立て方）を学校のリポジトリに置く
- 役割分担: サーバーは学校の管理下、部屋情報の更新は教職員、仕組みの手入れは学生
